Agent Experience Intelligence.

An evidence layer that turns real agent runs into verified, reusable skill intelligence—starting with coding agents.

Measure before claiming benefit.

01 / Problem

Agents rediscover solutions and lose execution experience.

Teams retain code and final answers, but rarely retain a trustworthy account of attempts, failures, recovery, cost, and the conditions under which a result was reproduced.

REPEAT

Execution resets

New sessions repeat exploration that a previous run already paid for.

FLATTEN

Outcomes hide the path

A merged fix does not explain the failed attempt, the recovery, or the guardrail.

GUESS

Advice outruns evidence

Unverified tips can look as credible as reproducible experience.

02 / Thesis

Put verified experience between agent execution and the next decision.

Capture the run, normalize the reusable signal, verify the outcome, recommend only relevant experience, and feed the new result back into the system.

CAPTURE

Run receipt

Attempts, failures, recovery, outcome, cost.

NORMALIZE

Safe record

Portable structure, sanitized content.

VERIFY

Evidence

Oracle, provenance, limitations.

RECOMMEND

Match

Explain relevance or abstain.

REUSE

Guidance

Apply, test, rate, recapture.

03 / Product boundary

A focused evidence layer for coding-agent workflows.

AEG complements runtimes, tools, models, and observability. It is not a generic marketplace, an agent orchestrator, or a replacement for LangSmith.

05 / Limitations

What the evidence does not say.

  • No demonstrated success-rate improvement
  • No generalized cross-project transfer claim
  • No proven reduction in retries, tokens, cost, or latency
  • No customer, production-adoption, or product-market-fit evidence
  • One transfer pair and one failed-path prevention pair were not positive

06 / Next validation

Test retrieval on fresh, blinded coding tasks.

Compare baseline and AEG-assisted runs where retrieval is the intentional difference. Measure success, retries, commands, tests, non-cached tokens, wall time, regressions, and abstention quality.

Decision rule

Relevant prior experience should reduce retries, token usage, or execution time without lowering task success. Negative and neutral outcomes remain part of the product evidence.
