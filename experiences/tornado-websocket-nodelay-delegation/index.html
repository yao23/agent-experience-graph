# Restore WebSocket TCP_NODELAY delegation after stream ownership moved

- Experience ID: `trace-2026-08-03-tr-04-tornado-nodelay`
- Verification: `LOCALLY_VERIFIED`
- Category: Framework Regression
- Last verified: 2026-08-03T06:53:21Z

Trace the public wrapper through the protocol ownership boundary, reject a suite-green wrong-surface patch, and delegate TCP_NODELAY to the active stream.

## Symptoms

- WebSocketHandler.set_nodelay no longer reaches the active network stream after stream ownership moves behind the protocol object.
- A plausible proxy repair can pass the existing suite while changing the wrong client-side API surface.
- The focused public caller contract fails even though legacy tests can remain green.

## Exact error signatures

- AssertionError on the obsolete handler stream

## Apply when

- A public wrapper delegates a control to a resource whose ownership moved behind another abstraction.
- The issue names a public entry point whose full delegation chain can be tested.
- A focused contract test can assert the call on the currently active resource.

## Do not apply when

- Do not reuse when the wrapper intentionally owns an independent stream.
- Do not accept a green suite without a focused assertion beginning at the public caller named in the issue.
- Do not treat this collection run as causal evidence that AEG retrieval improves repairs.

## Known limitations

- The successful second attempt was evaluator-informed because comparison occurred after the first frozen candidate targeted the wrong API surface.
- Historical CPython 3.7 was unavailable; CPython 3.8.20 required a temporary cancellation compatibility shim for four unrelated timeout-cancellation logs.
- This collection run is not causal evidence that AEG retrieval improves repairs.

## Environment and agent context

- Language: Python
- Runtime: CPython 3.8.20 used in place of unavailable CPython 3.7
- Operating system: macOS arm64
- Dependencies: Tornado historical test suite, temporary cancellation-only Python 3.7 compatibility shim removed before candidate hash verification
- Agent: Codex
- Model: unknown
- Harness: bounded BugsInPy work-queue collection
- Reasoning context: unknown

## Failed approaches

1. **Add delegation on a plausible client-side WebSocket surface.**
   - Observed: The existing suite passed, but evaluator comparison showed that the patch targeted the wrong public surface.
   - Why it failed: The repair did not begin at WebSocketHandler.set_nodelay or follow the current server-side ownership chain.

## Verified recovery

1. Start at the exact public method named in the issue and identify the resource it is expected to control.
2. Trace ownership through each abstraction until the currently active stream is found.
3. Add a focused contract test that calls the public wrapper and asserts delegation on the active stream.
4. Route the wrapper through the protocol object instead of retaining the stale direct stream reference.
5. Run the focused regression, related WebSocket tests, and the complete historical suite.
6. Keep environment-only compatibility shims outside the candidate patch and recheck the candidate hash after removing them.

## Verification

The corrected regression failed before repair and passed after repair; 46 WebSocket tests passed with one skip, and the complete historical suite passed 1,146 tests with 50 skips.

- corrected regression before repair: 1 AssertionError failure
- corrected regression after repair: 1 test passed
- upstream WebSocket suite: 46 passed, 1 skipped
- complete historical suite: 1,146 passed, 50 skipped, exit code 0
