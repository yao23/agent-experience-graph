## Material delta 1 — LifeMem separates environment-aligned traces from environment-invariant skills

Primary source: [LifeMem: Enabling Lifelong Experience Reuse for LLM Agents](https://arxiv.org/html/2609.12655), v1, 2026-09-11; [official code/data repository](https://github.com/BITHLP/LifeMem).

**Author-reported experiment (not locally reproduced):**

- LifeMem clusters trajectories by functional workflow before distilling skills. At inference it retrieves concrete trajectories only from the target environment, while higher-level skills can cross environments.
- Evaluation covers 10 environments, 12,489 training instances and 1,230 test instances across three model families.
- In two zero-shot transfers, LifeMem reports gains over memory-free ReAct of 17.9–22.5% for FEVER and 15.8–18.8% for τ-bench airline. The paper also exposes the counterexample: raw retrieval can fetch action-space-incompatible trajectories and reduce performance.
- The mean initial-query context is 2.18k tokens versus 1.88k for Synapse (+300); the paper attributes a 12.63% relative performance improvement to this added structure. AutoSkill uses 4.68k tokens because its global skill profile injects irrelevant cross-environment behavior.
- Failure/ablation evidence is mixed rather than universal: on individual categories, LifeMem is not always best and backward transfer is negative in some model/task cells. Over-clustering can overfit rollout noise.

**Inference for this pilot:**

- A valid transfer arm should contain two explicitly different input classes: (a) environment-aligned neutral execution material identical in both arms; (b) one environment-invariant experience artifact present only in treatment. Raw source trajectories, public analyses, queue text, and evaluator oracle must not leak through class (a).
- The current `#3494` block remains valid. LifeMem does not provide an isolated-solver substrate or prove non-inheritance.
- If a future retry is separately authorized, pre-register the exact bytes and token count for both input classes. Report treatment overhead separately; do not inject a global experience bundle.

**Candidate ranking/tool reuse impact:**

- No evidence justifies displacing the already READY historical replay.
- After that replay, the result strengthens the existing preference for structurally related lifecycle/regression cases (for example the queued cross-module `#2816`) over unrelated packaging work when all other eligibility factors are equal, because validator and failure-mechanism reuse is more likely. This is a research recommendation only; no queue edit is made.

## Material delta 2 — LifeFuse-Mem makes context lifetime an explicit variable

Primary source: [LifeFuse-Mem: Lifecycle-Aware State Fusion Against Temporary Overwriting for Long-Term Memory](https://arxiv.org/html/2609.12436), v1, 2026-09-11.

**Author-reported experiment (not locally reproduced):**

- The paper isolates “temporary overwrite”: run-local information silently becomes durable and displaces persistent knowledge.
- Its controlled benchmark requires lifecycle labels at write time plus known phase boundaries and query lifecycles. Under these explicit signals, reported acquisition-controlled retention improves from 57.72% to 63.71% on Qwen3-4B and from 60.27% to 69.39% on SmolLM3-3B versus δ-Mem.
- The authors explicitly do **not** claim autonomous lifecycle discovery; public long-memory benchmarks lack the required phase/lifecycle labels and are used only as compatibility checks.

**Inference for transfer-input isolation:**

- Input isolation needs lifecycle metadata, not merely separate filenames. At minimum distinguish `durable-policy`, `run-local-neutral`, `treatment-only-experience`, and `evaluator-only-forbidden`, and bind each item to the phase in which it may be read.
- A solver that has already seen queue/oracle material cannot be made fresh by deleting text later. Therefore the current `BLOCKED_TRANSFER_ISOLATION` status should not be relaxed based on cleanup alone.
- Evidence for any future authorized retry should include fresh-context identity, input manifest hashes, deny/read logs for forbidden paths, and post-run disposal state. This proposal is not execution authority.

## Material delta 3 — Trace2Flow supports review, but not a throughput claim

Primary source: [From Review to Reuse: How Post-Task Workflow Can Support Human-AI Agent Interaction](https://arxiv.org/html/2609.13136), v1, 2026-09-11.

**Author-reported human study (not locally reproduced):**

- Trace2Flow converts traces into editable post-task workflow graphs. The study used 20 participants and prompt/agent-error review tasks.
- Correct validation rose to 74% (17/23 sessions) when participants cross-checked sources; in the workflow condition, combined output, workflow and source checking reached 85% (11/13).
- Workflow reuse did not produce statistically significant gains over prompt reuse in follow-up-task success, completion time, or difficulty. Mean completion time was slightly longer (6:12 versus 5:24).

**Inference for verification tooling:**

- A graph/replay view is useful as a review index, but it is not an objective oracle and must not count as an independent verification observation.
- The existing pilot should continue requiring cross-source evidence: trace/action record + repository diff/state + deterministic test/oracle. A generated workflow alone cannot establish success, applicability, transfer, or token savings.
- This result does not change candidate order; it narrows how a future report UI may be used.
